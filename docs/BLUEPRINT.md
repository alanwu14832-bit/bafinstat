# BAFIN Stats — 儀表板設計藍圖 (Design Blueprint)

> 喝FIN就好BA 棒球數據平台：資料架構、視覺系統、版面、圖表風格與建置順序。
> 目標是一個「看起來像高預算 SaaS」但由一位紀錄員就能維護的系統。

---

## 1. 產品定位與資訊架構

| 層 | 內容 | 使用者 |
|---|---|---|
| **紀錄層** | Excel 總表（`data/BAFIN_棒球數據總表.xlsx`）：單場模板 → 打席／投球／守備紀錄表 | 紀錄員（比賽當天） |
| **計算層** | 總表公式（Excel）＋ TypeScript 統計引擎（網站，`web/src/data/stats.ts`）— 兩者定義一致，以 `data/stat_dictionary.json` 為唯一真相 | 自動 |
| **呈現層** | React 儀表板（總覽／打擊／投球／守備／球員／比賽／匯入／字典） | 教練、球員、全隊 |

**單一資料流**：每個打席一列（long format）→ 所有統計皆由列資料即時彙總 → 篩選（杯賽／日期／守位／對手／主客／勝敗）只是改變彙總的範圍，永遠不需要重算或維護第二份數據。

```
單場-摘要 / 單場-打擊 / 單場-投球  ──貼上值──▶  打席紀錄 / 投球紀錄 / 守備紀錄  ──▶  總表（Excel 公式）
                                                        │
                                                        └──上傳 .xlsx──▶  網站解析（SheetJS，只讀輸入欄）──▶ 統計引擎 ──▶ 頁面
```

## 2. 視覺系統

### 2.1 色彩（tokens.css）

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `--bg` | `#f6f7f4` | `#0e1311` | 頁面底（帶綠的石墨色：夜間球場） |
| `--surface` | `#ffffff` | `#151c19` | 卡片 |
| `--surface-2 / -3` | `#eef1ec / #e4e8e2` | `#1c2521 / #243029` | 次要面、hover、靜音長條 |
| `--ink / --ink-2 / --muted` | `#101512 / #4b554f / #7d8781` | `#f2f4f0 / #b8c2bb / #7d8781` | 文字三階 |
| `--accent` | `#d98d1c` | `#f0a72e` | **球場燈光琥珀色**：只用於 UI（作用中導覽、主要按鈕、示範標籤），**永遠不當圖表序列色** |
| `--series-1…8` | dataviz 驗證過的 8 色（藍／橘／青／黃／桃／綠／紫／紅） | 同色相調整亮度 | 圖表序列，**固定順序**：1 = 我隊，2 = 對手 |
| `--seq-100…700` | 藍色單色階 | 同 | 落點熱區、失誤分佈等「量」的編碼 |
| `--good / --warning / --critical` | `#0ca30c / #fab219 / #d03b3b` | 同 | 勝／和／敗、警告；不作序列色 |

規則：色彩跟著實體走（我隊永遠藍、對手永遠橘），篩選後不重新配色；圖表文字永遠使用文字 token，不穿序列色。

### 2.2 字體

- **Display**：Barlow Condensed 600/700 — 字標「BAFIN」、頁標題、KPI 數字、eyebrow（大寫、字距 .08em）。
- **Body**：Noto Sans TC 400–700 — 所有中文與內文；fallback PingFang TC / Microsoft JhengHei。
- 表格與座標刻度使用 `tabular-nums`；大數字用比例字。

### 2.3 形狀與層次

- 卡片圓角 12px、髮絲線邊框、無陰影（只有 hover 才出現一層柔陰影）。
- 不使用漸層、不使用 emoji 圖示（lucide icons）。
- 狀態靠形狀＋顏色（Badge：勝／敗／和／示範），不靠顏色單獨表達。

## 3. 版面

```
┌──────────┬──────────────────────────────────────────────────────────┐
│ Sidebar  │ TopBar：頁名 ｜ 全域篩選列（杯賽 日期 守位 對手 主客 勝敗）｜主題 匯入 │
│ 248/72px ├──────────────────────────────────────────────────────────┤
│ 總覽     │ PageHeader（eyebrow / 標題 / 說明）                       │
│ 打擊     │ 示範資料 banner（若有）                                   │
│ 投球     │ KPI 列：grid(auto-fit, minmax(180px,1fr)) 6 格            │
│ 守備     │ 圖表：2 欄（lg），1 欄（<lg）                              │
│ 球員     │ 表格：全寬，卡片內水平捲動                                │
│ 比賽     │                                                          │
│ 匯入     │ max-width 1440px，內距 24px（手機 16px）                  │
│ 字典     │                                                          │
└──────────┴──────────────────────────────────────────────────────────┘
```

- **Sidebar**：展開 248px／收合 72px，framer-motion 寬度補間（0.28s，cubic-bezier .22 1 .36 1），文字淡出＋位移，圖示位置不跳動；作用中項目用琥珀色藥丸＋左側 3px 條，`layoutId` 在項目間滑動；Ctrl/⌘+B 切換；狀態存 localStorage。<1024px 變成抽屜（背景模糊、Esc／點背景關閉、鎖捲動）。
- **全域篩選列**只有一列，所有圖表與表格都吃同一個切片（dataviz 規則：不在卡片內放篩選）。
- **響應式斷點**：375（手機）／768（平板）／1280（桌機）；表格永遠在自己的容器內捲動，頁面不出現水平捲軸。

## 4. 資料視覺化風格

| 需求 | 形式 | 規格 |
|---|---|---|
| 單一數字（戰績、打擊率、ERA） | **StatTile** | 34px display 數字、從 0 數上去（1.1s）、可附 12 點 sparkline 或 delta |
| 比較（逐場得失分、各守位失誤） | **長條** | ≤24px 粗、資料端 4px 圓角、基線方角、相鄰 2px 留白、單序列可 highlight 一根 |
| 走勢（累積得失分差） | **面積** | 2px 線 + 10% 同色填充 + 零線 |
| 走勢（OPS、ERA 滾動） | **折線** | 2px、僅終點圓點（r=4，2px 白環）、十字游標 tooltip |
| 組成（滾／飛／平） | **甜甜圈** | ≤6 段、2px 留白、中央英雄數字 |
| 佔比（好壞球、強擊） | **堆疊長條** | 段與段 2px 留白 |
| 個人能力（隊內百分位） | **雷達** | ≤2 序列、15% 填充 |
| 落點／失誤位置 | **SprayChart（自製 SVG 球場）** | 1–9 守位圓點，藍色單色階編碼數量，中心標 安打/場內球 |

共通：格線髮絲實線、無軸線（只留基線）、刻度 12px muted、≥2 序列必有圖例、tooltip 為小卡片。進場動畫：recharts 900ms ease-out ＋卡片上浮 0.5s；`prefers-reduced-motion` 時全部關閉。所有圖表資料都能在同頁表格看到（不靠 tooltip 才能讀值）。

## 5. 建置順序（實際執行順序，可重現）

1. **解析原紀錄表** → `data/game_20251010_qunfeng.json`（局數由 I/II/III 出局碼還原，核對逐局得分）。
2. **定義數據字典** `tools/stat_dictionary.py`（103 項：中英文、公式、現有／新增、P0–P2）→ 匯出 JSON 供網站。
3. **建 Excel 總表** `tools/build_workbook.py`：設定 → 名單 → 比賽清單 → 三張長表（輸入欄 + 灰色公式欄）→ 總表（篩選格 + SUMIFS/COUNTIFS）→ 單場模板 ×3 → 字典；LibreOffice 重算 258,983 條公式，0 錯誤。
4. **研究報告** `docs/ANALYTICS_RESEARCH.md`（Statcast 2024–2026、CPBL 官方欄位與 Trackman、差距分析、公式附錄）。
5. **UI 殼** `web/`：Vite 7 + React 19 + TS + Tailwind 4 + framer-motion + recharts 3；tokens、AppShell、Sidebar、TopBar、UI 元件、圖表元件。
6. **資料層**：`types.ts`（欄位 = 總表欄位）→ `stats.ts`（與 Excel 公式一對一）→ `filters.ts` → `xlsx.ts`（SheetJS 匯入／匯出）→ `store/data.ts`（localStorage 持久化）→ `demo.ts`（可關閉、有標籤的示範資料）；vitest 以 10/10 比賽驗證。
7. **頁面**：總覽 → 打擊 → 投球 → 守備 → 球員 → 比賽（Box Score）→ 匯入 → 字典；全域篩選列接上 store。
8. **驗證**：`npm run typecheck && npm test && npm run build`；headless Chromium 在 1366／390 寬、明暗兩主題截圖檢查（無水平捲軸、無 runtime error）。
9. **部署**：`.github/workflows/deploy.yml`（GitHub Pages，`VITE_BASE=/bafinstat/`）；`npm run build:single` 產生單檔預覽。
