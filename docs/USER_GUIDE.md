# NTU BaFiN 數據平台 使用手冊

整個流程只需要一份 Excel 總表（`data/BAFIN_棒球數據總表.xlsx`）和網站。網站上的「使用指南」頁有同樣內容。

## 一、角色分工
| 角色 | 做什麼 | 需要登入？ |
|---|---|---|
| 紀錄員 | 比賽當天記錄、賽後貼回總表、上傳網站 | 是（Supabase 帳號） |
| 隊員／教練 | 開網站看數據 | 否 |

## 二、比賽前（5 分鐘）
1. 打開總表（建議放在共用雲端硬碟，整隊只維護這一個檔案）。
2. `比賽清單` 新增一列：比賽ID `G+日期+場次`（例 `G20251010-01`）、日期、杯賽、對手、主客、場地。杯賽與對手名稱先在 `設定` 的清單裡加好，之後下拉選單才有。
3. 複製三張模板：右鍵工作表 → 移動或複製 → 建立副本：`單場-摘要`、`單場-打擊`、`單場-投球`。在 `單場-摘要!C2` 填同一個比賽ID，填先發打序與守位；賽後在同一區塊填勝投／敗投／救援（網站的 W／L／SV 由這裡來）。

## 三、比賽中：用哪一張表

> **不想用 Excel？** 紀錄員登入後到網站「紀錄比賽」頁：填比賽資訊與先發（會帶入「先發陣容」頁排好的陣容，否則帶上一場打序；球員一律下拉選）→ 每球點 B／CS／SS／F／IP → 點結果 → 確認落點與跑者去向 → 送出。局數、出局、壘上、得分、殘壘、結果代碼全部自動；每球送出後自動存到雲端、全隊即時看得到進度（自動儲存失敗時會出現「重試儲存」），賽後「結束比賽」填勝敗投（中繼可以複選）即完成。從賽程與「先發陣容」帶入的比賽資訊和打序會先收成摘要，要改再按「修改」；滾地、飛球類結果會自動帶入軌跡。
>
> 打席區上方的狀態列告訴你現在在記「打擊」（我隊進攻）還是「投球」（對方進攻，預設只記第幾棒；想記姓名見下方「對方打者」說明）。壘上跑者點一下可記盜壘、牽制（安全或出局）、進壘；「全螢幕」讓紀錄頁佔滿整個畫面；「大字」把按鈕和字放大一級（大太陽下比較好看，這台裝置會記住）。按鈕下方的狀態列會說最新一球是否已同步到雲端（綠點已同步、黃點尚未同步、紅字同步失敗＋「重試儲存」）。
>
> **相簿**：照片放在攝影師自己的 Google Drive（資料夾設「知道連結的人可檢視」），紀錄員到「相簿」頁把連結貼在對應的比賽；隊員不用登入，點「開啟相簿」就能看和下載原檔。
>
> **比賽時間、對方投手、對方打者**：第一球和最後一個打席的時間會自動記下（紀錄畫面下方出現「13:07 開賽」），「結束比賽」時帶出開賽、結束時間和比賽時間，可以修改（看影片補記請改成實際時間）。我隊第一次打擊時畫面上方會問「對方投手是？」，點「左投」或「右投」就好（也可以「填姓名」或「不記」）；對方換投時點「代打」旁的「對方 右投」改成新的投手，之後每個打席自動記上，用來看對左投／對右投的成績（雲端要先執行 2026-10-14 的 SQL，見 SUPABASE_SETUP.md）。對方打者姓名預設不記；開始前勾「記對方打者姓名」就能填對方打序，比賽中改名字＝代打。這些姓名和其他資料一樣公開，建議只記背號（例如「12號」）。

> **賽程**：紀錄員在「比賽」頁的「賽程」分頁新增下一場（日期、時間、對手、場地、集合備註），隊員可一鍵加到 Google 日曆；比賽當天在「紀錄比賽」的「從賽程帶入」選這場就開始記，不必重填。
>
> **先發陣容**頁：先選「這份陣容是哪一場」，球場圖上每個守位一個下拉選單、右邊排打序（「依守位填入」一鍵排好、可上下移），再在「板凳（今天有到）」點選到場但沒先發的人，需要時勾「允許被換下的球員再上場」；陣容存在這台裝置，可複製成文字貼群組，或「帶到紀錄比賽」（直接開那一場）。
>
> **逐球跑壘**：投球之間的盜壘、暴投、捕逸、牽制都記在「第幾球之後」：紀錄時點計分條上的壘包打開跑者面板，點跑者、再點發生的事；暴投／捕逸全部進壘直接按投球按鈕下方的「暴投」「捕逸」。賽後「修改資料」點一個打席，在「逐球」區選第幾球後、哪位跑者、發生什麼即可補記，點逐球裡的事件可刪除。安打時趁傳多跑的壘：在「跑者去向」把他設到比預設更遠的壘，旁邊出現「趁傳？」點一下即可（修改資料也一樣）。Excel 的「跑壘事件」欄是同樣的內容（例如「2 暴投 1-2；3 盜壘 2-3」），可不填。
>
> **延長賽突破僵局**：預設從規定局數的下一局起（系隊第 8 局），每個半局一開始一、二壘有人、無人出局；一壘跑者是這局第一位打者的前一棒，二壘是前兩棒（WBSC 規則）。打到那一局時，紀錄畫面先出現「延長賽突破僵局」卡片，列出誰上哪一壘和接下來的打者，按「放上跑者」就排好（記錯按「復原」）；這局不用按「這局不用」。開賽前可在比賽資訊的「突破僵局」選從第幾局起或「不採用」、「放哪幾壘」選一、二壘／二壘／滿壘（這台裝置會記住）；比賽中在卡片上按「改規則」。卡片出現時投球按鈕會先停用，換投、代打照常可以按；要代跑，放上去後點壘包換人。這些跑者**不算打席、打數**；他跑回來算他自己的得分，打回他的人照算打點；對方的突破僵局跑者回來得分一律是**非自責分**（規則視同失誤上壘，但不算失誤）。賽後在「修改資料」延長局的標題按「＋ 突破僵局跑者」可以補上（網站沒存預定局數，所以按鈕出現在第 5 局之後、平手打進來的局；比賽已經有突破僵局跑者時，從那局起每局都有；後面打席的壘上跑者會跟著更新，得分可能改變，打點請自己核對），點那位跑者可以改名字、代跑或「刪除這局的突破僵局跑者」。Excel：每位跑者記一列，放在那局最前面（先二壘、再一壘），打擊結果填「突破僵局」、逐球空白；壘上(前)、出局(前)照放上去的順序填（無、2…、0），得分、盜壘、結果代碼照一般跑者記；總表不會把這列算成打席。
>
> **投手犯規**：壘上有人時才有（壘上沒人時的違規投球照規則記一個壞球）。點計分條上的壘包打開跑者面板，按最上面的「投手犯規・全部進壘」：所有跑者各進一壘、這一球不算，打席繼續。我隊投手的投手犯規次數（BK）在「投球」頁「進階」看得到（只在網站計算，Excel 總表不算）；被投手犯規推進回來的分算自責分，沒有打點，也不算盜壘。賽後在「修改資料」點那個打席，在「逐球」選第幾球後、按「投手犯規」，會一次移動所有跑者。Excel 的「跑壘事件」欄寫成「2 投手犯規 3-H；2 投手犯規 1-2」（每位跑者一筆）。
>
> **板凳與當日登錄名單**：紀錄比賽時，換投、代打／換人的選單會先列出板凳（標「板凳」），被換下場的人標「已下場」且預設不能再選，這場允許的話在換人工具裡勾「允許再上場」。「換人」可以選任一棒，我隊守備時也能用（守備調動；不選人就是只改守位）。每次換人（代打／代跑／守備／換投、第幾局）都會記下，存檔時連同先發與板凳存成這場的**當日登錄名單**。賽後在「比賽」點那一場，「攻守成績」最下方的「當日登錄名單」列出先發、替補上場（替誰、第幾局）與未上場。以前的比賽沒有名單，先發與替補由打席紀錄推定；紀錄員可以在「修改資料」的「登錄名單」分頁補上或修正（先發、板凳、允許再上場、清除替補紀錄）。
>
> **報名名單**：杯賽要先報名的，紀錄員到「球員」頁展開名單 →「報名名單」→「新增報名名單」，選年度、填杯賽（例如 2026 大專盃）、點選報名的球員後儲存；同年同杯賽只有一份，再存一次會覆蓋。之後先發陣容與紀錄比賽選到那個杯賽的比賽時，候選名單只列報名的人；沒有名單的杯賽（友誼賽等）照常列出全隊。隊員不用登入也看得到名單；上方篩選選了杯賽時，球員名單可切換「全部球員／報名名單」，報名的人標「已報名」。

| 情境 | 工作表 | 每列 |
|---|---|---|
| 我隊進攻 | `單場-打擊` | 一個打席 |
| 對方進攻 | `單場-投球` | 對方一個打席（主角是我方投手） |

**單場-打擊 欄位**：局、出局(前)、壘上(前)、棒次、守位、打者、球1…球12、打擊結果、落點、軌跡、強度、盜壘、盜壘失敗、失誤進壘、壘死、得分、打點、結果代碼、備註。
**單場-投球 欄位**：局、出局(前)、壘上(前)、對方棒次、投手、對方打者、球1…球12、打擊結果、落點、軌跡、強度、被盜壘、阻殺、暴投、捕逸、牽制出局、結果代碼、備註。

### 代碼
- 逐球：`SS` 揮棒落空・`CS` 未揮棒好球・`S` 好球（未分類）・`F` 界外・`IP` 擊進場內・`B` 壞球
- 打擊結果：一安／內安（內野安打，算一安；預設只有被迫的跑者進壘）／二安／場地二安（彈出或卡在全壘打牆，算二安，跑者都進兩個壘）／三安／全壘打／保送／故四／觸身／三振／內滾／內飛／外飛／界外飛／野選／失誤／犧觸／犧飛／雙殺／妨礙；延長賽照規則放上壘的跑者填「突破僵局」（不是打席）
- 落點：出局填處理球的守備員 1 投 2 捕 3 一壘 4 二壘 5 三壘 6 游擊 7 左 8 中 9 右；沒人碰到的穿越安打填縫隙代碼 56 三游／46 二游／34 一二／78 左中／89 右中
- 名單守位：P／C／1B／2B／3B／SS／LF／CF／RF／DH，或彈性的 IF 內野手／OF 外野手／UT 工具人
- 軌跡：G 滾地／F 飛球／L 平飛；強度：強／中／弱
- 結果代碼：I／II／III 此打席造成第 1／2／3 個出局・L 殘壘・R 得分（投球表 R 非自責、ER 自責）
- 壘上(前)：無／1／2／3／12／13／23／123

### 小規則
- 雙殺打：只在打者列填代碼，跑者列不要重複填（那一列算 2 個出局）。
- 跑者在壘上出局（盜壘失敗、被觸殺）：在該跑者的列填「壘死」並給出局代碼。
- 球員名字要和 `球員名單` 完全一致。

## 四、比賽後（10 分鐘）
1. 檢查 `單場-摘要`：自動算出逐局比分、每人打擊／投球成績；核對 R/H/E。守備區塊填每個人的 PO/A/E（至少填失誤；沒填的 PO／A 網站會由投球紀錄推定）。
2. 貼回總表：`單場-打擊` 有資料的列（A 欄到「對方投手慣用」欄，最後一個黃色欄；灰色自動欄不用）複製 → `打席紀錄` 最後一列下方 **貼上值**；`單場-投球` → `投球紀錄`；守備區塊 → `守備紀錄`。`總表` 立刻更新。
3. 上傳網站：資料匯入 → 密碼登入 → 拖入檔案 → 「合併（略過重複的比賽ID）」。全隊即時看到。
   整份總表、只含三張「單場-」工作表的檔案、或舊格式的單場紀錄表都可以上傳，網站會自動辨識格式並算出一樣的數據：空白的「局」「出局(前)」由出局碼補算，「犧牲」等舊用詞自動對應，沒有守備紀錄時由打席守位與失誤落點推定，並列出需要核對的警告。
4. 貼完可以刪掉單場副本，或保留當存檔。

## 五、賽後怎麼看數據
- **總覽**：戰績、得失分、OPS 走勢、逐局得失分、落點熱區；上方篩選列選杯賽／期間／對手／主客。
- **打擊／投球**：基本、進階、過程指標三組欄位；點標題排序、點球員進個人檔案。
- **比賽**：逐局比分、Box Score、當日登錄名單（先發／替補上場／未上場）、逐打席打擊／投球逐球紀錄。
- **球員**：個人數據、隊內百分位雷達、落點分佈、逐場紀錄；展開名單可看各杯賽的報名名單。
- **數據字典**：每項指標的定義與公式。

## 紀錄員輔助：投手休息表、練習紀錄、紀錄員小抄

### 投手休息表
- 「投球」頁右上角「投手休息表」（網址 /pitching/rest，不用登入）：依 **MLB Pitch Smart 19–22 歲的建議**（不是聯盟規定），列出每位投手最近 30 天出賽的日期與用球數、要休幾天、最早哪天可以再投，以及單日超過 120 球、休息不夠就出賽、一天投兩場、連續 3 天出賽、打席沒記球數等提醒。「看哪一天」可以選今天、接下來的賽程或自訂日期。
- 預設級距：1–30 球不用休、31–45 球休 1 天、46–60 球休 2 天、61–80 球休 3 天、81–105 球休 4 天、106 球以上休 5 天；一天最多 120 球、不要連續 3 天出賽、一天只投一場。
- 紀錄比賽時，投手用球數下面會寫「需休 N 天」，快到下一級時提醒「再投 X 球就要多休一天」；休息還沒滿就上場的投手會先寫「休息未滿，10/12（一）起才建議出賽」（橘色）；換投名單標出誰還在休息、誰最近 3 天投過；開賽設定和先發陣容選了投手時會提醒他還要不要休息。這些都只是提醒，不會擋住換投。
- 用球數是紀錄的每一球加總；打席還沒結束就換局（例如盜壘出局結束半局）的那幾球沒有算進去。
- 規則寫在 `web/src/config/teamDefaults.ts` 的 `pitchRest`（每隊各自一份，改了重新部署就生效）。

### 練習紀錄
- 「紀錄比賽」頁上方按「練習紀錄」（還沒登入的話，按登入框下面的「開始練習」；網址 /record?practice=1）：畫面和正式紀錄一樣，**不用登入、不會存檔**。練習只存在這台裝置（和正式比賽的進度分開），不會同步到雲端、不會出現在即時比分，也不算進任何數據。
- 練習中計分條旁有「練習」標籤；按「結束練習」→「結束（不存檔）」就回到練習設定頁。舊版網站（/v/…）沒有練習模式。

### 紀錄員小抄
- 「使用指南」→「紀錄員小抄」（網址 /guide/cheatsheet）：紀錄比賽的每個按鈕和代碼（逐球、打擊結果、落點、軌跡、強／中／弱怎麼判斷、跑者面板、結果代碼、常見情況），按「列印」可以印成一張 A4（深色模式也會印成淺色）。內容從網站的按鈕設定自動產生，按鈕改了小抄也會跟著改。

## 六、常見問題
- **讀取錯誤或記錯了**：到「比賽」點那一場 → 右上角「修改資料」，比賽資訊、每個打席、守備都能直接改、增刪列，儲存後統計立即重算（雲端模式需先登入）。
- **改了某場資料要重傳**：上傳時選「以此檔取代雲端全部資料」。
- **名字打錯**：總表尋找取代後，用取代模式重傳。
- **ERA 局數**：預設 7 局制；`設定` 工作表或網站資料匯入頁可改 9。
- **寄信登入被限制**：用密碼登入（Supabase → Authentication → Users 設定密碼）。
- **提示「請管理員在 Supabase 執行 supabase/migrations/2026-09-26_rosters.sql」**（管理員）：雲端資料庫還沒加上當日登錄名單（`games.day_roster`）與報名名單（`registrations` 表）。到 Supabase 的 SQL Editor 執行一次這個檔案（重複執行安全），詳見 [SUPABASE_SETUP.md](SUPABASE_SETUP.md)。執行前比賽照常紀錄與儲存，只是登錄名單不會存進雲端、報名名單無法使用、候選名單列出全隊。

## 七、把以前的單場紀錄表匯進來
舊格式（當日比賽統計／打　擊／投球守備）的檔案可以直接轉換：
```bash
python3 tools/convert_single_game.py 舊檔.xlsx --id G20251222-01 --tournament 友誼賽
```
會產生 `data/games/G20251222-01.json`；再執行 `python3 tools/build_workbook.py` 重建總表，網站重新建置後也會內建這場。轉換器會把逐打席推算的逐局得分和記分板比對，不一致時列出警告，請回頭核對原表。
